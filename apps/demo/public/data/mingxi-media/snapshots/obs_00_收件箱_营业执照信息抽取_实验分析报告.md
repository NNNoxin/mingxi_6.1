## 一、实验配置

| 项         | 配置                                                             |
| --------- | -------------------------------------------------------------- |
| 被测模型      | qwen3-vl-chat-8b-instruct（视觉语言模型 VLM）                          |
| 部署        | 本地 vLLM，OpenAI 兼容接口 `http://192.168.0.194:8000/v1`             |
| 采样参数      | `temperature=0`、`max_tokens=2048`，其余默认（无 repetition_penalty）   |
| Prompt 指纹 | `4d766115`（system+user prompt 的 sha1 前 8 位，prompt 一改即变）        |
| 抽取字段      | 9 个固定字段（顺序固定）：统一社会信用代码、企业名称、类型、住所、法定代表人、注册资本、成立日期、营业期限、经营范围    |

| GT oracle | 百度「营业执照识别」API（`business_license`），与被测模型不同源（避免循环偏置）             |
| 信用代码校正    | 文件名内嵌 18 位真实信用代码 → 覆盖百度读错的值（94/95 有真值）                         |

**评测归一化规则**（`eval_metrics.py`，比较前对两侧同样处理）

| 字段 | 归一化 |
|---|---|
| 成立日期 | 统一成 `YYYY-MM-DD` |
| 营业期限 | 串内所有日期归一为 `YYYY-MM-DD`，分隔符统一为「至」 |
| 注册资本 | 去掉「人民币」「整」、去多余小数零（`100.0000万元`→`100万元`） |
| 经营范围 | 模糊匹配（SequenceMatcher 相似度 ≥ 0.90 算对） |
| 其余 | NFKC 全角转半角 + 去空格后精确匹配 |

**判定类别** 正确(tp) / 值错(wrong) / 漏报(miss，GT 有值预测空) / 多报(spurious，GT 空预测有值) / 正确留空(tn)

## 四、Bad case 原因分析

共 **49 条** bad case，按根因分桶：

| 代号 | 原因 | 条数 | 性质 |
|---|---|---|---|
| A | 模型整图退化（经营范围跑飞→JSON 未生成→全字段漏） | 18 | 真实失败，集中在 2 张图 |
| B | 信用代码字符误读（1/I/L、0/O/C 等混淆） | 14 | 真实模型弱点 |
| C | GT 残缺（百度漏读，qwen 反而更全） | 1 | ⚠️ 误判，qwen 实际对 |
| D | 住所细节差异（漏字/截断/标点/门牌） | 9 | 多为真实差异，部分待 gold 判 |
| E | 法定代表人误读 | 4 | 真实模型误读（含 1 漏读） |
| F | 企业名称误读 | 2 | 真实模型误读 |
| G | 经营范围差异（实为百度 GT 错字） | 1 | ⚠️ 误判，qwen 实际对 |
| | **合计** | **49** | |

> **关键洞察**：49 条里至少 2 条（C、G）是百度 GT 自己错、qwen 反而正确，silver 口径把它们误算成 qwen 的错 → 真实指标比上表更高。这正是必须做人工 gold 的原因。

**A. 模型整图退化（18 条 / 2 张图）**

经营范围超长时，8B 模型陷入重复/幻觉（"…宠物用品零售；宠物用品零售…"乃至编出"宠物Transformer护理产品销售"），输出撑满 token 仍未闭合 JSON → 整张解析失败、9 字段全漏。加 `repetition_penalty` 只能救其中 1 张，另一张更严重。

- `KANGCUN-...91310113MA1GQ1JC7P-1.jpg`（上海屹达文化传播有限公司）
- `KANGCUN-...91310113MA7CBJB37P-1.jpg`（上海茗曜汽车服务有限公司）

**B. 信用代码字符误读（14 条）** — 18 位字母数字串里错 1~2 个字符，典型 OCR 混淆：

| GT（真值） | qwen 预测 | 错处 |
|---|---|---|
| 92310113MA1L1**C**KA5R | 92310113MA1L1**X**KA5R… | C→X |
| 92310113MA1L**1**PUC09 | 92310113MA1L**I**PUC09 | 1→I |
| 92310113MA**1**L1FHE7E | 92310113MA**L**L1FHE7E | 1→L |

→ 密集小字符 OCR 是该尺寸 VLM 的天然弱点（视觉 patch 压缩后细节丢失）。

**C. GT 残缺，qwen 实际正确（1 条）⚠️**

| 字段 | 百度 GT | qwen 预测 |
|---|---|---|
| 住所 | `室` | `上海市宝山区陆翔路1018弄3号地下1层41室` |

百度只读出一个「室」字，qwen 读出完整地址 → qwen 对，GT 错。

**D. 住所细节差异（9 条）**

| 百度 GT | qwen 预测 | 差异 |
|---|---|---|
| 上海市宝山区顾北**东**路575弄1-17号 | 上海市宝山区顾北路575弄1-17号 | 漏「东」 |
| …陆翔路1018弄5号地下1层4**2室-1** | …陆翔路1018弄5号地下1层**2** | 尾部截断 |
| …松兰路879号**-**185 | …松兰路879号185 | 标点 |

地址长、门牌结构复杂，差一字/一标点即判错；部分需 gold 才能定谁对。

**E. 法定代表人误读（4 条）** — 人名生僻字/形近字误读（晴→丽、璇→凝）

| 百度 GT | qwen 预测 |
|---|---|
| 严桢 | （漏读，空） |
| 马晴龙 | 马**丽**龙 |
| 韦嘉璇 | 韦嘉**凝** |

**F. 企业名称误读（2 条）**

| 百度 GT | qwen 预测 |
|---|---|
| 上海良**驹**汇马术俱乐部有限公司 | 上海良**狗**汇马术俱乐部有限公司 |
| 上海**旭樊**足部保健有限公司 | 上海**恒健**足部保健有限公司 |

**G. 经营范围差异，实为百度 GT 错字（1 条）⚠️**

| 百度 GT | qwen 预测 |
|---|---|
| **大只**销售、大只寄养、大只美容(不得从事犬**其养结**与诊疗) | **犬只**销售、犬只美容（不得从事犬只**繁殖**与诊疗） |

百度把「犬只」误读成「大只」、「繁殖」误读成「养结」，qwen 才是对的 → 又一例 GT 错、qwen 对。

## 五、结论与建议

1. **整体表现好**：宏平均 F1 ≈ 0.95；类型/成立日期/注册资本/营业期限/经营范围/企业名称均 ≥ 0.96。
2. **两个真实弱点**：
   - 信用代码（真实准确率 ≈ 84%）：密集字母数字串字符误读，是 8B VLM 的固有短板；
   - 超长经营范围：会触发重复/幻觉，导致整图失败（2/95）。
3. **silver 低估**：至少 2 条 bad case 是百度 GT 错、qwen 对（C、G），住所/人名里可能还有更多。真实指标应高于本报告。
4. **建议**：
   - 尽快用 `review_server.py` 定稿 gold，`--gt-dir gold` 重算真指标；
   - 信用代码：可叠加专用 OCR / 提高输入分辨率 / 后处理校验位（GB 32100）兜底；
   - 长经营范围：加 JSON 修复/重试兜底，或对该字段单独用更大模型（如 qwen3-32b）。
