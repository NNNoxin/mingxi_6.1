## B. 前端交互与界面

- [ ] **B1（M1）** 前端交互的功能设计是核心产品设计，**绝对不能变**，主要参考明晰 demo 5 的界面。
  - 处理：demo 5 的界面组件与 CSS 原样迁入 `packages/ui`；只把写死的数据与 `fetch` 抽成数据源接口（演示剧本 / 真实后端两种实现）。
  - 验收：Playwright 视觉回归——原版 demo 5 与新仓库在 40 步产品导览每一步的截图逐像素对比，差异为 0（允许字体抗锯齿阈值 ≤ 0.1%，超出需逐张人工确认并说明）；`data-tour` 标记集合完全一致。
  - 证据：
- [ ] **B2（M1）** 千万不要改动前端交互界面，保持跟原来明晰 demo 一模一样；**不要自己重新编前端 demo**，那是好不容易调好的。
  - 处理：禁止重写任何页面；禁止新增 UI 元素。真实后端需要的错误、加载、空态，一律复用原界面已有的位置（如对话气泡“这次没有梳成：…”、画布提示条、`mwb-empty`）。
  - 验收：同 B1；另外代码评审确认 `packages/ui` 相对原版的 diff 只包含「数据源注入」类改动，并逐处列出。
  - 证据：
- [ ] **B3（M1）** 两个 Agent 仓库（logic chain、knowledge completion）各有自己的界面，跟明晰 demo 不一样 → 思考界面如何统一，比较：
  - 方案一：尽量把交互界面统一成明晰 demo 的样式；
  - 方案二：拆成两部分——一部分专门做 demo 演示（全部虚拟、单独抽离），另一部分接真实前后端和大模型 API，真实测试交互与 Agent 功能（可用不同 UI，或跟 Agent 保持一致）。
  - 处理：docs/02 §1 给出两方案对比与推荐，由用户在 **D1** 拍板。
  - 证据：
- [ ] **B4（M2）** 产品前端不要变；只要产品设计和想要的功能保持不变。
  - 处理：同 B1/B2。功能清单以 demo 5 的四个工作区（笔记库 / 领域旭日 / 梳逻辑线 / 扩展）+ 笔记阅读页 + 外查核实 + 手机端 + 产品导览为准，见 docs/01 §2。
